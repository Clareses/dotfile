# Agent 文档的分层最佳实践（AGENTS.md / skills / triggers）

> 提炼自 Firefox 大仓（数千万行代码，根 `AGENTS.md` 仅 73 行）的做法。
> 用途：`repo_structure` 工具在 `format="agents"` 生成脚手架时，模型据此填充内容。

## 一句话
**别把提示词写长，去建立它该在的地方。**

## 放置决策（"Where should this live?"）

| 类型 | 放哪 | 判据 |
|---|---|---|
| **Scope** | 目录自己的 `AGENTS.md` | 只对某模块成立 |
| **Pointer** | 指向**被维护**的文档 | 已有权威文档，别抄副本 |
| **Tool** | 一个命令 / 工具 | 能"让正确的事变简单" |
| **Skill** | 按需加载的知识文件 | 长知识，且有**常驻成本**（description 每 session 都加载） |
| **Trigger** | 由"改了什么文件"决定 | 该不该带某段指引，不该靠人记 |

## 六条原则

1. **根文件只放"处处皆真"**。构建/测试命令、全局硬规则、安全红线。
   反例：一个 1000+ 行的根文件试图解释一切 → 改个错别字也要读一大段。
2. **Scope > Prompts**。根文件列目录 → "在这里工作就打开这里的 `AGENTS.md`"。
   指令没变短，是**有了作用域**。
3. **Pointer > Prose**。能指向维护中的文档就**别复述**；副本会过期。
4. **Tool > Prompts**。与其写"请仔细搜索/有耐心"，不如给它一个搜索工具/命令。
   *一句话是请求模型守规矩；一个工具让正确的事变简单。*
5. **Lazy > Always**。长知识放按需加载处；常驻部分（description）当**接口**写：
   何时用、**何时别用去用哪个别的**。
6. **只写"代码告诉不了你的"**——那些陷阱、约定、审批要求。

## 防腐烂

- **引用名字，不引用位置**：用函数/类/文件/键的**名字**，别写行号、
  别写"上面那条规则"。需要定位就用**钉在某个 revision** 的链接。
- 提示词和注释一样"没有东西检查它"——编译器不会提醒你某条指令过期了。
  能交给工具/lint 的，就别写成散文。

## 生成流程（本工具 + 模型）

1. 调 `repo_structure`（`format="digest"`）拿机械结构摘要。
2. 据此判断：哪些是"处处皆真"，哪些该下沉到子目录，哪些已有文档可直接指过去，哪些其实是工具/触发器的活。
3. 调 `repo_structure`（`format="agents"`）拿脚手架，按上面六条原则填充、**删掉用不上的小节**。
4. 用户同意后再 `write=true` 落盘；已存在的 `AGENTS.md` 不会被覆盖。
